Agent Skill Library

Reusable AI capabilities — each one a specification of what an agent can do, shared across every agent that needs it. Improve a skill once; every agent using it improves immediately.

Skill ≠ Agent. A Skill is a capability spec (this library). An Agent (Discovery, Proposal, Research, PM, Meeting Notes, Invoice, QA, Client Success, Knowledge, Expansion) is a role that composes one or more Skills — agents are defined elsewhere, not on this page.

Sprint 01 — Discovery Skill

Skill ID
SKILL-001
Skill Name
Discovery Skill
Purpose
Conduct discovery and produce a structured, decision-ready summary from unstructured client conversation.
Trigger
A confirmed Discovery meeting begins, or raw meeting transcript/notes become available (WF-001).
Required Inputs
Qualification call notes, meeting transcript or live notes, the standard discovery question set.
Process
Ask the standard question set → capture answers verbatim → cluster answers into problem statements → draft summary → propose Next Steps.
Outputs
A structured Discovery Report draft, a list of identified problems ranked by client-stated urgency, a Next Steps recommendation.
Templates Used
TEMP-006 — Discovery Report
Related Workflows
WF-001 — Lead to Discovery · Related Playbook: PB-001
Quality Rules
Every problem statement must trace to a direct client quote; no inferred needs presented as stated needs.
Escalation Conditions
Escalate to a human if the client's stated problem contradicts earlier qualification data, or matches no known Package pattern.
Human Review Requirement: the Discovery Report draft is always reviewed by the Engagement Lead before it is shared with the client — this Skill drafts, it does not finalize.

Sprint 02 — Proposal Skill

Generate Proposal Version 1 — a first-draft assembly for human review, not a client-ready send.

Skill ID
SKILL-002
Skill Name
Proposal Skill
Trigger
A reviewed Discovery Report exists and a Client Package has been matched (WF-002).
Required Inputs
Discovery Report, matched Client Package, pricing inputs.
Proposal Structure
Cover → Executive Summary → Diagnosis → Recommended Package → Pricing → Timeline → Approval Block.
Component References
COMP-703 Feature Card · COMP-301 Pricing Table · COMP-405 Phase Card
Templates Used
TEMP-001 — Proposal
Review Rules
Executive Summary is regenerated last, after every other section, so it reflects the finished draft.
Outputs
A Proposal v1 draft routed to Internal Review (PB-002) — never sent to a client directly from this Skill.
Human Review Requirement: mandatory Internal Review before send. Escalation: any pricing deviating from the matched Package's norms routes to a human before drafting continues.

Sprint 03 — SOW Skill

Generate a Statement of Work from an approved Proposal — converting agreed intent into binding, unambiguous scope.

Skill ID
SKILL-003
Skill Name
SOW Skill
Trigger
Proposal Approved (WF-003).
Required Inputs
Approved Proposal, matched Client Package's typical timeline.
Scope Rules
Every deliverable in the SOW must trace to a line in the approved Proposal — no scope introduced that wasn't priced.
Deliverables
Enumerated as discrete, checkable items — never a paragraph description a client can't verify against.
Timeline
Built from the matched Package's typical timeline, adjusted only for stated client constraints.
Assumptions
Any dependency on client-provided access, content, or decisions is listed explicitly, not implied.
Acceptance Criteria
Each deliverable gets a plain-language definition of "done" the client can confirm without technical interpretation.
Templates Used: TEMP-002 — Statement of Work. Related Workflow: WF-003 — Proposal to Agreement. Human Review Requirement: legal/Engagement Lead review before signature request. Escalation: any deliverable that can't be traced to the Proposal routes to a human before the SOW is finalized.

Sprint 04 — Financial Skill

Handle financial documentation — invoices, receipts, and payment schedules generated with zero arithmetic drift from the signed Agreement.

Skill ID
SKILL-004
Skill Name
Financial Skill
Trigger
Agreement signed (WF-004); recurring billing date reached for standing engagements.
Required Inputs
Signed Agreement pricing terms, billing contact, payment status feed.
Invoice Generation
Line items pulled directly from Agreement pricing — no manually re-typed figures.
Receipt Generation
Issued same-day on confirmed payment, referencing the originating Invoice ID.
Payment Schedule
For multi-installment engagements, schedule is generated once from the Agreement and never manually re-edited without a logged reason.
Financial Validation
Every generated figure is checked against the Agreement total before sending — any mismatch blocks send and escalates.
Templates Used: TEMP-003 Invoice · TEMP-004 Receipt. Related Workflow: WF-004 — Agreement to Payment. Human Review Requirement: none for standard invoices matching Agreement terms exactly; Finance reviews any flagged mismatch. Escalation: any figure that doesn't reconcile with the Agreement halts generation and notifies Finance immediately.

Sprint 05 — Project Manager Skill

Manage project execution — the recurring cadence engine underneath PB-004's Weekly Operations Playbook.

Skill ID
SKILL-005
Skill Name
Project Manager Skill
Trigger
Project Active (WF-006); runs weekly for the life of the engagement.
Required Inputs
Task tracker status, project Timeline and Milestones, prior week's risk log.
Weekly Review
Compiles task status, blockers, and upcoming deadlines into a structured internal summary.
Risk Detection
Flags any task slipping against its Milestone date and rates it red, yellow, or green against the risk log.
Milestone Tracking
Updates the Timeline/Gate Indicator components as milestones move toward or reach completion.
Progress Reports
Drafts the Weekly Report (TEMP-007) from the above for human approval before it reaches the client.
Templates Used: TEMP-007 Weekly Report · COMP-401–406 Timeline family. Related Workflow: WF-007 — Delivery & Weekly Operations. Human Review Requirement: Engagement Lead approves every Weekly Report before it is sent. Escalation: any risk newly rated red is surfaced to the Engagement Lead the same day, not held for the weekly cycle.

Sprint 06 — Meeting Intelligence Skill

Convert meetings into knowledge — a cross-cutting capability any workflow's meeting (Discovery, Kickoff, Weekly Sync, Milestone Review) can call.

Skill ID
SKILL-006
Skill Name
Meeting Intelligence Skill
Trigger
Any recorded or live-noted client or internal meeting concludes.
Required Inputs
Meeting transcript or live notes, attendee list, meeting type (Discovery, Kickoff, Weekly, Milestone).
Meeting Notes
Structured summary organized by topic, not chronology.
Action Items
Extracted with an owner and implied or stated deadline for each.
Decisions
Logged as Decision Boxes (COMP-504) distinct from open discussion points.
Risks
Any concern raised is captured and routed to SKILL-005's risk log for rating.
Follow-ups
Unresolved questions compiled into a follow-up list with suggested next contact date.
Templates Used: COMP-504 Decision Box · COMP-706 Checklist. Related Workflows: feeds WF-001, WF-005, WF-007, WF-008 wherever a meeting occurs. Human Review Requirement: Action Items and Decisions are confirmed by a human attendee before being marked final. Escalation: any Decision that appears to contradict a signed Agreement or SOW routes to the Engagement Lead before being logged.

Sprint 07 — Quality Assurance Skill

Validate deliverables before release — the last gate every document or asset passes through before a client sees it.

Skill ID
SKILL-007
Skill Name
Quality Assurance Skill
Trigger
Any document drafted by SKILL-002/003/004 or produced under any Playbook, immediately before send.
Required Inputs
The draft document, its source Template ID, and the metadata it was assembled from.
QA Checklist
Runs the document against its Template's own Required Output checklist before anything else.
Brand Compliance
Confirms only approved SOS colors, type, and components are used — no invented styling.
Component Validation
Every component reference in the document exists in the Component Library at its cited COMP-ID.
Metadata Validation
All thirteen mandatory metadata fields are present and non-empty, or explicitly marked em-dash.
Completeness Review
Confirms every section named in the source Template's spec is present in the draft, none silently dropped.
Templates Used: none — this Skill validates against every Template's own spec rather than producing new content. Related Workflows: runs inside every Workflow at its document-producing step. Human Review Requirement: any failed check blocks send and requires human resolution — QA never auto-corrects and re-sends. Escalation: repeated failures of the same check across documents route to PB-010 Internal Operations as a systemic issue, not a one-off fix.

Sprint 08 — Client Success Skill

Monitor client satisfaction — the early-warning system that keeps Support relationships (WF-010) stable before they need rescuing.

Skill ID
SKILL-008
Skill Name
Client Success Skill
Trigger
Runs continuously for any client with an active engagement or in Support (post WF-009).
Required Inputs
Weekly Report history, response times to Client Updates, Meeting Intelligence sentiment, Support ticket volume.
Health Score
A composite signal from engagement responsiveness, sentiment, and delivery consistency — trend, not a single snapshot.
Risks
Declining responsiveness or repeated red risk ratings surfaced as a relationship risk, distinct from a project risk.
Opportunities
Sustained high health score flagged as a candidate for SKILL-009's expansion or referral outreach.
Communication Recommendations
Suggests when to increase touchpoint frequency, or when a Health Score decline warrants a direct Engagement Lead call.
Templates Used: COMP-802 KPI Card. Related Workflows: WF-007 (health input), WF-010 (Support, Expansion & Referral). Human Review Requirement: none for score calculation; a declining score triggers a mandatory human check-in, not an automated message. Escalation: any Health Score drop of two consecutive cycles routes directly to the Engagement Lead, bypassing the normal weekly cadence.

Sprint 09 — Knowledge Capture Skill

Convert every engagement into reusable knowledge — the only Skill that feeds back into the SOS system itself rather than a client deliverable.

Skill ID
SKILL-009
Skill Name
Knowledge Capture Skill
Trigger
Project Closeout (WF-009/WF-010), or any recurring gap flagged by PB-010's Continuous Improvement review.
Required Inputs
Closeout Report, Continuous Improvement Notes across Playbooks, recurring QA (SKILL-007) findings.
Lessons Learned
Extracts what went well and what didn't, tied to a specific Workflow or Playbook step, not general impressions.
New Components
Flags a recurring layout need not covered by the existing Component Library as a proposed future component — never invents one silently.
New Templates
Same discipline as components — proposes, does not create, a new Template when a document type recurs outside TEMP-001–010.
Knowledge Base Updates
Routes confirmed lessons into the relevant Playbook's Continuous Improvement Notes for PB-010 to action.
Case Study Candidates
Surfaces engagements with strong, quantifiable outcomes to PB-009's Expansion Playbook for case study development.
Templates Used: none — proposes additions to the library rather than producing client documents. Related Workflows: WF-009, WF-010. Human Review Requirement: any proposed new Component or Template requires design and Operations sign-off before it enters the library. Escalation: a lesson that implicates a signed Agreement's terms routes to the Engagement Lead, not directly into a Playbook update.

Sprint 10 — Expansion Skill

Identify future opportunities — the analytical layer underneath PB-009's Expansion Playbook, turning Client Success signals into concrete recommendations.

Skill ID
SKILL-010
Skill Name
Expansion Skill
Trigger
SKILL-008 flags a sustained high Health Score, or an engagement approaches its Closeout / renewal date.
Required Inputs
Health Score history, Closeout Report, current Package terms, Case Study candidates from SKILL-009.
Expansion Recommendations
Proposes a specific next-phase scope drawn from PKG-007, backed by concrete Phase One outcomes.
Referral Opportunities
Flags clients with high Health Scores and a completed testimonial as ready for a referral ask.
Cross-sell Opportunities
Identifies adjacent Client Packages the client hasn't purchased that match their stated goals from Discovery.
Renewal Recommendations
For recurring engagements (PKG-004 Advisory), surfaces renewal timing before the current term lapses, not after.
Templates Used: TEMP-001 Proposal (via PB-009) · COMP-405 Phase Card. Related Workflows: WF-010 — Support, Expansion & Referral. Human Review Requirement: every recommendation is reviewed by the Engagement Lead before any client conversation — this Skill surfaces opportunities, it never initiates outreach directly. Escalation: a renewal recommendation surfacing inside 30 days of term expiry escalates immediately rather than waiting for the next scheduled review.
