Component Family 06

Approval

Components that record who signed off, who's still pending, and what was decided.

Every approval component is built for evidence — it must hold up as a record months after the document was signed.

COMP-501
Primary Variant

Approval Block

Purpose: Lists everyone required to sign off, and where each stands. Used on: the closing pages of Proposals, SOWs, and Agreements.

RoleNameStatusDate
Engagement LeadJ. AlvarezApproved07/08/2026
Client SponsorA. WhitfieldPending—
Layout
Table: role, name, status badge, date. Rows always ordered by approval sequence, not alphabetically.
Typography
Status cell reuses the Status Badge component exactly (Family 03) — never a re-drawn variant.
Spacing
7–8px cell padding, matching the Approval Chain pattern established in the Financial and Timeline tables.
Accessibility
Pending rows always show an em dash in the date column, never a blank cell.
Print / PDF
Header repeats if the chain spans a page break; a row is never split from its status badge.
COMP-502
Primary Variant

Signature Block

Purpose: Physical or digital signing line for a named signer. Used on: the final page of any Agreement or SOW requiring wet or e-signature.

SignatureDate
J. Alvarez
Engagement Lead, Major AI Mindset
SignatureDate
A. Whitfield
Client Sponsor, Aurelia Capital Partners
Layout
Two-column grid by default (signer + counter-signer); scales to a single column when only one party signs.
Typography
Name Archivo 600, 12px; title/company Archivo 400, 10.5px muted — signature line itself carries no type.
Spacing
28px column gap; 40px signature line height to leave room for wet or digital ink.
Accessibility
"Signature" and "Date" labels are always printed beneath the blank line — the line is never presented unlabeled.
Print / PDF
Never split across a page break; the whole block, name, and title move together.
COMP-503
Primary Variant

Approval Timeline

Purpose: Shows the sequence and dates a document moved through review to approval. Used on: audit-sensitive documents — Agreements, formal Change Orders.

06/28/26
Drafted and submitted for internal review
07/02/26
Internal approval — Finance, Legal
07/08/26
Sent to client for signature
Layout
Vertical log: date column (fixed width) + dot + event text. Most recent event in gold, prior events in ivory.
Typography
Date in mono 10px; event text Archivo 400, 12px.
Spacing
9px row padding, 12px gap between date/dot/text columns, fixed 80px date column width for alignment.
Accessibility
Reads top-to-bottom in chronological order — the log never reverses order to "most recent first."
Print / PDF
A log entry never splits from its date and dot across a page break.
COMP-504
Primary Variant

Review Notes

Purpose: Captures a reviewer's comment attached to an approval step. Used on: Approval Blocks and Decision Boxes where a sign-off carries a condition or caveat.

R. Chen — Finance07/09/2026
Approved pending confirmation of the payment schedule in Section 4 — please reissue before countersignature.
Layout
Gold left-border note, reviewer + date on one line, comment text below — same accent treatment as a Highlight Card.
Typography
Reviewer name Archivo 600, 11.5px; date mono, muted; comment Archivo 400, 11.5px.
Spacing
14px left padding from the border, 6px between the byline row and comment text, max-width 520px for readable line length.
Accessibility
Reviewer role is always stated alongside the name — never name alone, which can be ambiguous across a large org.
Print / PDF
Kept whole; a note is never allowed to print with its comment separated from its byline.
COMP-505
Primary + Alternates

Decision Box

Purpose: States a single final outcome plainly — approved, declined, or deferred. Used on: Change Order responses and formal decision memos.

Decision
Approved
Decision
Declined
Layout
Bordered box, label above outcome — outcome is the single largest word in the box, no supporting copy inside it.
Typography
Outcome in Archivo Black 900, 16px, uppercase — one of the few places display weight sits inside a bordered card.
Spacing
12/18px padding; 14px gap when Approved/Declined appear side by side for comparison.
Accessibility
Border color (green/orange) always paired with the outcome word itself — never a colored box with no text.
Print / PDF
Always followed immediately by any Review Notes explaining the decision — never left to stand alone without rationale.
COMP-506
Primary Variant

Acceptance Certificate

Purpose: Formal, standalone confirmation that a full engagement or deliverable was accepted. Used on: the closing page of a Final Delivery Package.

Certificate of Acceptance
Q3 Advisory Engagement
Accepted as fully and satisfactorily delivered by Aurelia Capital Partners.
DOC-2026-00417 · Accepted 09/30/2026
Layout
Centered, gold-bordered, full-width card — the one Approval component that breaks the system's default left-alignment.
Typography
Certificate label in tracked mono; engagement name in Archivo Black 900, 22px, uppercase, centered.
Spacing
32/30px generous padding; centered tri-bar closes the statement before the identifier line.
Accessibility
Always carries the Document Identifier and acceptance date — a certificate with no traceable ID is never valid.
Print / PDF
Always occupies its own page, centered top-to-bottom — treated as a closing ceremony, not a data page.
