AG-001
Philosophy

Sprint 01 — AI Workforce Philosophy

Agent Categories

Every agent maps to one existing SKILL-XXX (Page 08) — this registry never introduces a new capability, only governs the ones already defined.

Human-in-the-Loop Philosophy

An agent drafts, validates, or recommends by default; only Financial Skill's exact-match invoice path (SKILL-004) runs unattended end to end — every other Skill's output waits for a named human before it reaches a client.

Escalation Philosophy

An agent that cannot complete its task with confidence escalates to a named human rather than guessing — silence or a best-effort guess is never an acceptable failure mode.

AG-003
Matrices

Sprint 03 — Skills & Capability Matrix

Skill Matrix

A grid of every Agent (rows) against every SKILL-XXX (columns) — each cell is a checkmark or blank, maintained in Airtable as a many-to-many link, never duplicated in prose per agent.

Permission Matrix

A second grid crossing Agent against Connected System, each cell marked Read, Write, or none — an agent with Proposal Skill gets Airtable Write on the Templates table only, never blanket Write access to every table.

Skill Dependencies

An agent cannot be granted a Skill whose Required Inputs (per Page 08) it has no Connected System access to satisfy — the dependency is checked at grant time, not discovered at runtime failure.

Read/Write Matrix & Restricted Systems

AG-005
Approval Levels

Sprint 05 — Human Approval Framework

Purpose

Clearly define where humans stay in control — the operational enforcement of AG-001's "agents execute, humans approve."

Draft Only
Agent output never leaves internal review — default for any new Skill.
Named Approver
A specific human (not a role) must approve before send — Proposal, Invoice, Contract.
Autonomous — Bounded
Runs unattended only within a validated range (e.g. SKILL-004 exact-match invoices).
Proposal: Agent drafts → Human approves Invoice: Agent prepares → Finance approves Contract: Agent drafts → Legal approves
AG-005
Escalation & Thresholds

Sprint 05 — Human Approval Framework

Escalation Rules

An agent operating at Autonomous — Bounded that hits a case outside its validated range escalates to Named Approver automatically, per AG-001's escalation philosophy — it never widens its own scope to cope.

Confidence Thresholds

Any agent producing a recommendation with stated confidence below a Skill-defined threshold routes to Draft Only regardless of its normal approval level — low confidence always downgrades, never upgrades.

Required Human Decisions

Pricing deviation from a Package norm, any client-facing legal language, and anything touching Confidentiality: Restricted or above always require Named Approver — no exceptions regardless of agent confidence.

Handoffs & Dependencies

Sprint 06 — Agent Collaboration Model

Handoffs

Each arrow is a Workflow transition (WF-001–010) — the Discovery Agent's output (Discovery Report) is the Proposal Agent's declared input, exactly matching DS-005's input/output chaining. An agent never hands off to another agent directly; it hands off through the Artifact or record the Workflow defines.

Dependencies

The Proposal Agent cannot start until the Discovery Agent's output is Approved (per AG-005) — a downstream agent never operates on an unapproved upstream draft.

Shared Skills

Meeting Summary Skill (SKILL-006) and Knowledge Capture Skill (SKILL-009) are used by more than one agent in this chain — shared Skills are still governed by the same single Skill Matrix (AG-003), never duplicated per agent.

AG-008
Access & Data Handling

Sprint 08 — Security & Compliance

Purpose

Protect clients and the operating system — security is not a separate concern from governance, it's AG-004's Permission Model enforced under adversarial assumptions.

Access Rules

Every agent authenticates with its own scoped credential — never a shared "AI service account" — so a single compromised credential never grants access beyond one agent's already-narrow permission set (AG-004).

Sensitive Data Handling

An agent never receives more of a record than its Skill's Required Inputs specify (DS-006) — a Proposal Agent sees pricing and scope, never a client's full financial history unless a Skill explicitly requires it.

AG-008
Confidentiality & Audit

Sprint 08 — Security & Compliance

Confidentiality

Any record marked Confidential or Restricted (DS-001) is off-limits to an agent unless that agent's Skill is explicitly named on the record's access list — inherited confidentiality blocks by default, never opens by default.

Audit Logs

Every read and write an agent makes is logged with Agent ID, timestamp, and record touched — the same durable trail as AG-005's approval audit, extended to cover routine access, not just approvals.

AG-008
Compliance, Incident Response & Required Output

Sprint 08 — Security & Compliance

Compliance Rules
Any agent touching a Client marked with a specific data-handling obligation inherits that obligation automatically from the Client record — never a manual per-agent checklist.
Incident Response
A suspected credential compromise or unexpected access pattern moves the agent to Suspended (AG-002 status) immediately, pending Owner and Operations Lead review — suspension is reversible, silence is not acceptable.
Related SOS Objects
DS-001 Confidentiality field, AG-004 System Permissions, AG-005 Audit Requirements
Completion Criteria
Every agent has its own scoped credential, every access is logged, and an incident response runbook exists naming who to notify and how fast.

AG-009
Versioning, Testing & Deployment

Sprint 09 — Lifecycle Management

Versioning

Agent versions follow GH-009's SemVer rules exactly — a MAJOR bump (e.g. a new Skill granted) requires the same Operations Lead sign-off as any breaking GitHub change.

Testing

Testing stage runs the agent against real (anonymized) past engagements — the same Practice Scenario approach as NT-008's human Readiness Check — before any live client ever sees its output.

Deployment

Production deployment starts at the most conservative Approval Level (AG-005) for that agent's category and only relaxes after a defined number of clean cycles — trust is earned incrementally, never granted at launch.

AG-009
Retirement, Archive & Required Output

Sprint 09 — Lifecycle Management

Retirement
An agent moves to Retired when its Skill is superseded or its Health Score (AG-007) fails to recover after review — retirement revokes all credentials and permission grants immediately.
Archive Rules
A Retired agent's full record (registry entry, audit logs, performance history) is retained indefinitely — never deleted, matching GH-008/NT-004's non-destructive archive pattern.
Related SOS Objects
AG-002 Status Lifecycle, GH-009 Versioning, NT-008 Training/Readiness Check
Completion Criteria
Every agent's current lifecycle stage maps cleanly to its AG-002 Status, and a retirement runbook exists specifying credential revocation as the first step.
